# Laya 微调

这篇讲怎么把一份官方 Laya 权重，训成「看这个游戏的局面，在几件要事里选一件」。
模型本身的前向过程在 [laya模型学习.md](./laya模型学习.md)。
训完之后用胜率而不是准确率做最终裁判，尺子在 [laya效果评估.md](./laya效果评估.md)。

本仓库用的包是 `laya` 0.4.7。训练入口是 `laya.train.finetune`，命令行是 `laya-train`。微调移动的是编码器和解码决策头的权重，不是从零预训练一个语言模型。

---

## 1. 微调在改什么

官方多语权重要学的是一般的「文字选项怎么选」。天合小队的要事（配平、清飞机、着陆压速、补设备、必填槽）不在那份数据里。未微调时，它在真题上的置信度中位数大约 0.09，和规划器的分歧在分叉实验里与 0 分不开（见效果评估）。

一次微调做这些事：

1. 读 JSONL 或 CSV。
2. 用和推理相同的 `build_sequence()` 把局面和选项变成 token。渲染方式和 `Agent._to_internal` 不一致的话，模型学的是它上线时看不到的句子。
3. 在多语 checkpoint 上做若干 epoch。默认损失是 RLCD；硬标签也可以用 `soft-ce`。
4. 从训练行里抽出一小片做温度校准，写进保存的 `rl_agent_config.json`。
5. 若提供了 `--eval`，先用原权重打分，训完再用新权重打分，打印前后差。

保存出来的目录用 `laya.load(目录)` 读取。`Router` 不会自动改用它。本仓库的服务认环境变量 `LAYA_CHECKPOINT`。

能改的范围：

| 部分 | 默认 | 冻住编码器时 |
|---|---|---|
| 编码器（mmBERT，约 768 维 × 22 层） | 学习率 `2.5e-5` | 不更新，只当特征提取器，dropout 也会关掉 |
| 决策头（2 层 Transformer + 打分网络） | 学习率 `1e-4` | 仍更新 |
| 温度、弃权阈值 | 训完用校准片拟合 | 同左 |

冻住编码器时，模型只能重组「原版中文编码器已经分开的方向」。原版若还没把「姿态 -1」和「飞机在 4」分成对要事有用的方向，只训头往往停在均匀分布上。把编码器放开，才有机会改这些方向；学习率过大时损失会炸，见第 8 节。

## 2. 标签从哪来

这个游戏没有标准答案。「该先清飞机还是先配平」只有走完之后的胜负。

两种标签，效果完全不同：

| 标签 | 模型最多学成什么 |
|---|---|
| 规划器这次选了哪件要事 | 规划器的模仿。分叉实验里它和规划器的差会靠近 0，不会超过规划器 |
| 同一局面、同一批骰子，哪条路胜率更高 | 有机会在规划器选错的那些点上改选择 |

本仓库用第二种。`test/ai/laya-finetune-data.js` 的规则：

1. 用规划器把一局走完（`fair: false`，`coop: 1`，`samples: 1`）。规划器自己的随机数固定成 0.5，骰子走可复现的种子，两条分叉才能配上同一批骰子。
2. 只在 `usablePriorities` 至少两件、且每件要事的最优落子互不相同的局面上出题。假题不写进行。
3. 每件要事取规划器在该要事里的最优落子，作为这一臂。用同一批种子各走到终局，默认每臂 16 局。
4. 胜局数领先不足 4（参数 `margin`）的丢掉。两条路差不多的局面写成硬标签，等于把噪声当答案。
5. 领先够了，`expected.move` 写成获胜选项的 key（`a` / `b` / `c`）。key 的顺序就是当时 `renderPriorities` 的顺序，和线上一致。
6. 每 5 局拿出 1 局整局进 `eval.jsonl`，其余进 `train.jsonl`。按局切开，避免同一局的前后手同时出现在训练和测试里。训练代码还会按 token 再查一次重叠。

命令：

```bash
node test/ai/laya-finetune-data.js [保留条数] [每臂局数] [最少净胜局] [输出目录]
# 默认：180 条，每臂 16 局，净胜至少 4，写到 data/laya-finetune/
```

2026-10-19 那次采集：

| 项 | 数 |
|---|---|
| 走完的局 | 2593 |
| 看过的真题（两臂落子不同） | 3816 |
| 领先不足、丢掉 | 3509 |
| 局面文字重复、丢掉 | 67 |
| 留下 | 240 |
| 其中赢家落子和规划器全局最优相同 | 69 |
| 训练行 / 留出行 | 193 / 47 |
| 耗时 | 1296 秒 |

留下的 240 条里，赢家分布大致是：清飞机、配平、着陆压速、补设备都有，必填槽很少。大约七成的赢家不是规划器那一步。这些行才是「有可能超过规划器」的老师；另外三千多条分叉结果差不多，写进去只会把模型往「两个都对」上拉，硬标签则会随机指定一个赢家。

一行长这样（字段 `wins`、`priorities` 等是给人看的，`laya.train` 只读 `state` / `questions` / `expected` 或 `gold`）：

```json
{
  "state": "你是副驾，第 3/7 轮\n高度 4000 英尺，……",
  "questions": {
    "move": {
      "type": "choice",
      "instructions": "你是副驾。机长和副驾合作，要在 7 轮内把客机安全降落。下面几件事现在都做得成。请只选一件最该先做的。",
      "criteria": {
        "a": "配平姿态：对手已放姿态 2，你可以把骰子放到 2，姿态回到 0",
        "b": "清开挡路的飞机：距离 4 有飞机，无线电可以清除"
      }
    }
  },
  "expected": { "move": "b" }
}
```

`criteria` 的 key 必须和 `expected` 里的字符串一致。线上 `laya_service.py` 会把选项文字截到 120 字；现在的要事句子都短于这个长度，训练和推理看到的是同一句。以后若把选项写长，训练数据要做同样的截断。

软标签用 `gold` 而不是 `expected`。两条路都经常赢时，用胜局比例，不要硬指定一个：

```json
"gold": { "move": { "probabilities": { "a": 6, "b": 10 } } }
```

概率按 key 对齐到选项顺序，负数或非有限值会报错；总和为 0 时变成均匀分布。`items_from_rows` 在两者都有时优先用 `gold`。

不要把「每件要事做不做」写成独立的 `noul`。几件要事抢同一颗骰子，模型可以全部答「做」。若选项经常多于两个，用固定顺序的两两比较，并且训练和上线用同一种顺序。比较顺序一变，标签的含义就变了。

## 3. 官方训练接口

```bash
laya-train \
  --data data/laya-finetune/train.jsonl \
  --eval data/laya-finetune/eval.jsonl \
  --base multilingual \
  --out models/sky-laya \
  --loss soft-ce \
  --epochs 8 \
  --micro-batch 2 \
  --grad-accum 4 \
  --shuffle-options \
  --device mps
```

`--base` 可以是别名（`multilingual`、`english`）、Hub id，或本地目录。本地目录里要有 `rl_agent_config.json`。中文游戏用 `multilingual`。

`TrainConfig` 里和命令行一一对应、以及命令行没暴露但代码里有的旋钮：

| 字段 | 默认 | 含义 |
|---|---|---|
| `epochs` | 4 | 大语料上的默认。一两百条时 4 轮往往不够，包会警告「预测塌成类别先验」 |
| `micro_batch` | 8 | 一次前向的条数 |
| `grad_accum` | 8 | 累积几次再更新。有效批大小 = 两者相乘。笔记本是 8×2 卡×4 = 64；单卡用 8×8 |
| `encoder_lr` / `head_lr` | `2.5e-5` / `1e-4` | AdamW。头的学习率高于编码器 |
| `min_lr` | `1e-6` | 余弦退火的下限 |
| `weight_decay` | 0.01 | |
| `grad_clip` | 1.0 | |
| `loss` | `rlcd` | 另一个是 `soft-ce` |
| `rl_samples` | 4 | RLCD 每次在 logit 上采几份高斯噪声 |
| `sigma_start` / `sigma_end` | 0.4 / 0.1 | 噪声标准差随 epoch 从大到小 |
| `w_sph` / `w_rps` | 0.75 / 1.0 | RLCD 里 proper score 的两项权重 |
| `shuffle_options` | 空 | 设成 `("choice",)` 后，每个 epoch 打乱选项顺序，并把目标分布按同一置换重排。避免模型只记得「答案总在第一格」 |
| `freeze_encoder` | false | |
| `label_smoothing` | 0 | 只作用于硬标签 `expected` |
| `calib_frac` / `calib_max` | 0.1 / 400 | 从训练行里先切出校准片，再开始更新。温度不要拟合在刚训过的行上 |
| `max_len` / `head_max_len` | 跟 checkpoint | 写进保存的配置，推理用同一预算 |
| `amp` | 仅 CUDA 打开 | MPS 上保持关闭 |
| `gradient_checkpointing` | 跟随 `amp` | 16GB 上放开编码器时要显式打开，否则优化器状态容易撑满内存 |
| `eval_data` | 无 | 留出文件。训练前打一遍原模型，训完打一遍新模型 |
| `seed` | 0 | |

RLCD（默认损失）在 logit 上加零均值高斯噪声，噪声在该题自己的选项上做了中心化；每份噪声样本用 proper score 对目标分布打分，优势函数再去加权这份噪声的对数密度；最后加上一份 `soft-ce`。它是官方笔记本的目标，适合概率标签。标签是硬的「哪条路赢得多」、数据又只有几百条时，`soft-ce` 更直接：就是让正确选项的对数概率变大。

`soft-ce` 的实现：对 logit 做 log-softmax（非法位置填 `-1e4`），再按目标分布求交叉熵，只在这道题自己的选项上求和。两个选项、目标是 one-hot 时，均匀猜测的损失是 `ln 2 ≈ 0.693`。训练损失停在 0.69 附近，就是还没离开「随便猜」。

包在校准片上还会检查塌缩：校准交叉熵离 `ln K` 不到 2% 时警告。默认 4 个 epoch 在几百到一千条上经常触发，提示加 epoch、加数据或换种子。这是训练没学会，不是任务本身无解的证明。

校准：

- 温度按题型，以及按选项个数分桶（`choice:2`、`choice:3-5`、`choice:6-10`、`choice:11+`）。
- 拟合结果被夹在 `[0.5, 5]`。顶到 5 说明 logit 太小，温度只能把分布拉得更平，救不回选择。
- 弃权阈值要一个桶里至少 `min_abstain_n`（默认 10）条才拟合。不够就不要用置信度当开关。
- 校准片只有十几条时，包会警告「fitted on only N calibration items」。温度读数当参考，不要当生产门槛。

每个 epoch 结束会把权重写到 `输出目录/checkpoint_latest`。全部结束再写最终目录，并把校准后的温度合并进 `rl_agent_config.json`。不同行的 `questions.move` 结构不一致时，包保留第一行的 schema 并发出警告；选项个数本来就该随局面变化，这条警告可以忽略，只要每行自己的 `criteria` 和 `expected` 对得上。

## 5. 训完怎么接到游戏

```bash
LAYA_CHECKPOINT=models/sky-laya \
  /tmp/laya_run_venv/bin/python ai/laya_service.py
```

`LAYA_CHECKPOINT` 非空时，服务调用 `laya.load(目录)`，不再走官方 `Router`。`GET /health` 的 `checkpoint` 字段会带回这个路径。`POST /decide` 的 JSON 形状不变：`choice`、`confidence`、`probs`、`model`。

游戏进程仍然默认旁路。要让这件要事真正改落子：

```bash
AI_LAYA_APPLY=1 AI_LAYA_MIN_CONF=0.6 AI_ENGINE=laya node server.js
```

在温度校准可靠之前，不要开 `AI_LAYA_APPLY`。第 8 节那份权重的置信度集中在 0.5 附近，0.6 的门槛会把几乎所有选择挡回去，等于没接上。

Node 侧的 `fair` / `coop` / `samples` 必须和规划器那次 `rankMoves` 用同一份。`choosePriority` 接收调用方传入的 `searchOpts`，不要在 Laya 路径里另写一套默认值。`rankMoves` 在没传 `fair` 时默认 `fair: true`，和线上 `AI_FAIR=0`（全知）不一致；调用处要显式传 `fair: false`。

## 6. 怎么判断这版有没有用

两层尺子，都要看。

**第一层：留出题上的选择。** `finetune()` 在更新之前用原模型、更新之后用新模型，对 `--eval` 各跑一次。看 `Accuracy` 的差。和规划器的一致率不能当这个数：老师是胜率更高的那条路，规划器经常不是那条路。

这一层回答「它有没有学会老师」。原模型在二选一上大约一半，训完若仍在一半附近，选择没有变。

**第二层：决策点分叉。** 留出准确率上升之后，再跑：

```bash
# 服务先用 LAYA_CHECKPOINT 起在 7788
node test/ai/laya-value.js 150 40
```

参照臂是规划器全局最优，同一局面同一批骰子。对照组（规划器最差、随机合法）必须仍然明显更差，否则这把尺子当时不可信。Laya 臂的 Δ 才是「这一步对胜率的影响」。

注意效果评估第 7 节：大量决策在本轮内顺序不同、终态相同。即便选择学对了，整局胜率的空间也有限。整局胜率要分辨 2 个百分点，在 45% 的基线上大约要每臂近万局，不适合当作日常回归。

阳性对照：在留出文件的局面最前面写上答案，准确率应接近 1。若连这个都不上升，是训练循环或渲染和推理不一致，不是任务太难。

## 7. 一次完整的推荐流程

1. 采集，只留净胜够大的真题。先小跑确认速度：`node test/ai/laya-finetune-data.js 8 16 4 /tmp/laya-probe`。本机大约每条留下的样本数秒到十几秒，因为大部分时间花在被丢掉的平局上。
2. 看 `stats.json`。留下的条数里，`plannerSame` 若接近 100%，老师就是规划器，微调没有超过规划器的空间。2026-10-19 那次是 69/240，空间是有的。
3. 确认 `eval.jsonl` 至少有几十条，且训练日志里重叠条数是 0。
4. 用多语底模。先 `soft-ce`，选项打乱打开。16GB 上放开编码器时 `micro_batch=2`、打开 checkpointing。
5. 看训练损失是否离开 0.69。停在 0.69，就不要看准确率的第三位小数。
6. 留出准确率稳定高于 `1/K`（两选项时高于一半，并且不是只多对一两题），再跑 `laya-value.js`。
7. 分叉 Δ 不低于规划器、对照组仍然很差，才考虑 `AI_LAYA_APPLY=1`。置信度门槛等校准片够 10 条以上再定。

数据再生成时换一批游戏种子，避免把同一批 240 条反复训、反复测。

## 8. 2026-10-19 这版的实测

底模：多语 checkpoint。老师：上一节那 240 条，留出 47 条，训练代码报告与训练片、校准片的输入重叠为 0。校准片从训练行里另切了 19 条，实际更新用 174 条。设备：Apple M4，16GB，MPS。

三轮都跑完了，选择没有学会。

| 跑法 | 训练损失 | 留出准确率 | 留出损失 | 平均置信度 |
|---|---|---|---|---|
| 原模型（更新前） | — | 0.5319（25/47） | 0.8915 | 0.7656 |
| 编码器+头，`soft-ce`，编码器学习率 `1.5e-5`，头 `1e-4`，有效批 8，7 epoch，打乱选项，checkpointing | 停在约 0.69 | 0.5319，没变 | 0.6891 | 0.5124 |
| 只训头，头学习率 `5e-4`，30 epoch，打乱选项 | 从 0.75 降到 0.66，仍贴着 0.69 | 0.5106（24/47） | 0.6896 | 0.5157 |
| 只训头，头学习率 `1e-3`，权重衰减 0，40 epoch，不打乱选项。这是写进 `models/sky-laya` 的那份 | 最后一轮 0.6776 | 0.5532（26/47） | 0.6905 | 0.5120 |

准确率从 25 题到 26 题，是一题的波动。损失落到 `ln 2`，温度拟合顶在夹紧上限 5。ECE 从 0.34 降到 0.04，因为分布被拉平了，不是因为选对了。置信度从 0.77 降到 0.51，模型变得更像「两件里随便猜」。

另外两次探路：

- 只训头、24 条、不打乱、头学习率 `1e-3`、25 epoch：损失在第 19 轮掉到 0.42，随后又回到 0.54。小集合上能记住一点，一换到 174 条、并且每轮打乱选项，就记不住。
- 编码器学习率 `2e-4`、8 条、不打乱、20 epoch：第 4 轮损失到 2.27，随后在 0.7–1.2 之间晃。这个学习率在 MPS 上把编码器训散了。
- 编码器学习率 `1e-4`、174 条、12 epoch：前 8 轮均值仍在 0.69–0.70，这次被中止，没有当作交付权重。

结论：这两百条「哪条路赢得多」的文字题，现成的多语编码器还分不出方向；只训头重组不了这些方向；把编码器学习率加大则先发散。`models/sky-laya` 可以加载，它不是一版更会玩的棋手。上线继续用规划器，Laya 保持旁路。

这次没有把分叉实验再跑一遍。留出题上的选择几乎没变，分叉 Δ 不会离开原来的「与规划器分不开」。

## 9. 下一版值得改的地方

按这次读数，瓶颈在标签和特征，不在服务接线。

- **多采净胜够大的题。** 3816 道真题里只有 240 道领先至少 4 局。要让编码器离开 0.69，需要更多这种行，并且留出集按新的游戏种子另采，不要从这 240 条里再切。
- **学习率放在两次探路之间。** `1e-4` 训 8 轮还贴在 0.69；`2e-4` 在 8 条上已经发散。下一版若放开编码器，从 `5e-5` 量起，看到损失离开 0.69 再加 epoch，看到损失冲过 1 就停。
- **先确认渲染一致。** 用同一条 JSONL 走 `laya.load` 的 `predict`，key 必须落在 `criteria` 里。服务端 120 字截断要和训练数据一致。
- **不要用规划器的选择当老师**，除非目标只是模仿规划器。那份模仿即使准确率很高，分叉 Δ 的上限也是 0。
- **准确率的第三位没有意义。** 47 条上多对 1 题就是 2 个百分点。要宣称学到了，留出集需要大到这个差不是一题，并且 `laya-value.js` 的 Δ 同号。

CSV 也能训（`laya-train --text-column --label-column`），包会合成一道 choice。本游戏的选项每行都不同，用 JSONL 的 `questions`，不要用 CSV 把所有行合成同一组选项。
