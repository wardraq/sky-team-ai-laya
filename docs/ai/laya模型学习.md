# Laya 模型学习

这篇讲 Laya 是什么、一次选择在模型里怎么走完、以及《天合小队》为什么只让它挑「要事」。
微调的数据格式、命令和这次实验的读数在 [laya微调.md](./laya微调.md)。
提示词原文和 token 账本在 [laya提示词样本.md](./laya提示词样本.md)。
怎么判断它有没有让胜率变好，在 [laya效果评估.md](./laya效果评估.md)。

文中的结构数字来自本机缓存的 `convaiinnovations/laya`（snapshot `7b928d8`）和本仓库用过的 `laya` 0.4.7。

---

## 1. 它是什么

Laya 是一个**一次前向就给完答案**的决策模型，作者是 Convai，权重仓库 `convaiinnovations/laya`，协议 Apache-2.0。

一次调用的形状是：

```text
局面文字
+ 一道或几道题（每道题有类型、指令、若干选项）
→ 每道题一个分布：选了谁、概率、置信度
```

它不一个字一个字地往外写。选项在送进去之前就写好了，模型只负责给这些选项打分，再把分数变成概率。游戏里搜合法落子、模拟本轮后果，仍然是 `ai/planner.js` 的事。

三种题：

| 类型 | 问法 | 返回 |
|---|---|---|
| `choice` | 多个文字选项里选一个 | `choice` + 每个 key 的概率 |
| `score` | 一组有顺序的等级 | 期望等级（从 0 起） |
| `noul` | 一件事成不成立 | `P(成立)`，键固定是 `false` / `true` |

本游戏只用 `choice`。`score` 和 `noul` 走同一条前向、同一套编码器，只是打分头按题型加了一点类型向量。

## 2. 三份现成权重

`Router` 按文字脚本挑 checkpoint。中文多数会进多语版。中英夹杂时按字符数取众数，有一半可能被判成英文，所以这个游戏的提示词尽量写成纯中文。

| 名字 | 编码器 | 隐藏维 | 层数 | 词表 | 局面预算 `max_len` | 题干预算 `head_max_len` | 体量（仓库文档） |
|---|---|---|---|---|---|---|---|
| `english`（仓库根） | `answerdotai/ModernBERT-large` | 1024 | 28 | 50368 | 512 | 192 | 约 421M |
| `multilingual` | `jhu-clsp/mmBERT-base` | 768 | 22 | 256000 | 1024 | 256 | 约 322M |
| `typed-decisions` | 同一份 ModernBERT-large，在类型化决策数据上再训过 | 1024 | 28 | 50368 | 1024 | 256 | 约 421M |

两份编码器都是 ModernBERT 结构：每 3 层一次全注意力，其余层是窗口 128 的滑动注意力，位置用 RoPE，编码器本身最长能到 8192。Laya 另有自己的预算，不会把 8192 用满。多语版的词表是 256000，中文能切成较完整的词；英文版词表 50368，中文会被切得很碎，所以这个游戏固定走多语版。

多语配置里的训练记录：15987 次更新、4 个 epoch、约 5 小时、`fine_tuned_from_checkpoint: false`（这份多语权重是直接训出来的，不是从英文版接着训）。温度三个数都是 `1.0`，还没有按选项个数分桶。英文版和 typed-decisions 已经有分桶温度，例如 `choice:2`、`choice:3-5`。

本游戏启动时用：

```bash
LAYA_PRELOAD=multilingual python3 ai/laya_service.py
```

`preload` 为空时，`Router(preload=True)` 会把三份都拉下来。默认 LRU 只留一份在显存里，中英一换就要重建，冷启动大约 7–10 秒。

## 3. 一次选择的数据流

```text
局面 state                         题：instructions + 选项文字
        │                                    │
        ▼                                    ▼
   编码器词表切词                      拼成 head
        │                    choice question: 指令 [SEP]
        │                    [MASK] 选项A [MASK] 选项B ...
        └──────────────┬─────────────────────┘
                       ▼
              双向编码器（整段一起看）
                       ▼
         题型向量 + 2 层 Transformer 决策头
                       ▼
              只取出每个 [MASK] 位置的向量
                       ▼
                   打分头 → 一个分数
                       ▼
              无效位置掩掉，softmax → 概率
                       ▼
           温度把分布拉平或拉尖，再算置信度
```

服务端把 HTTP 正文收成 Laya 的题（`ai/laya_service.py`）：

```python
questions = {
    "move": {
        "type": "choice",
        "instructions": instructions,
        "criteria": {"a": "配平姿态：……", "b": "清开挡路的飞机：……"},
    }
}
router.predict(state, questions)
```

`build_head()` 实际写成：

```text
choice question: <指令> [SEP] [MASK] <选项a> [MASK] <选项b> ...
```

局面是另一段，接在后面。所以一条输入被切成两段预算：

- **head**：题型声明 + 指令 + 全部选项，多语上限 256 token。
- **state**：局面正文，多语上限 1024 token。

本游戏现在的要事提示词，head 大约 91–121，局面大约 151–169，整段大约 250–270，余量七成以上。明细见提示词样本。

选项写在局面前面。编码器是双向的，后面的局面仍然能流进前面的 `[MASK]`。如果换成只能看左边的因果编码器，选项上的 `[MASK]` 还没看见局面，分数就和棋盘无关。这也是 DeepSeek-V4.1 那种因果编码器不能原样塞进 Laya 的原因：序列布局是按「选项在前、局面在后、双向互通」定的。

## 4. 分数从哪来

每个选项前面有一个 `[MASK]`。编码器跑完之后，决策头只读这些位置上的向量。别的 token 的向量已经通过注意力混进 `[MASK]`，但打分不用它们。

决策头（`rl_agent_config.json` 里 `head_layers: 2`）：

1. 给整段隐状态加上题型向量，让同一套权重知道现在是 choice、score 还是 noul。
2. 再过 2 层 Transformer。
3. 按记录好的下标，把每个 `[MASK]` 的向量拿出来。
4. 打分网络把这个向量压成 **1 个实数**。选项有几个，就有几个实数。
5. 被预算裁掉、对不齐的位置填一个极小值，softmax 时概率接近 0。
6. softmax 得到概率。概率最高的 key 就是 `choice`。

多语版每个向量长 768。这 768 个数没有「第 0 维 = 姿态、第 1 维 = 飞机」这种人写的坐标。词表把「姿态」「-1」「飞机」「4」变成向量，注意力把它们和选项文字搅在一起，训练再把「该选的那个选项」往相关碎片上拉。推理时谁的 `[MASK]` 和当前这些碎片更合得来，谁的分数就高。

教学时用过的 `[1,0,0]`、`[0,1,0]`、`[0,0,1]` 只是把 768 个数收成 3 个数的示意图。它们代表三条不同的方向（配平 / 清飞机 / 补设备），不是程序给局面贴的标签，也不是选项在列表里的下标。真模型里没有人把「配平」指定成第一维。

置信度不是最高概率本身。代码里先算这个分布的归一化熵（除以 `ln K`，K 是选项数），置信度是 `1 - 熵`。两个选项 0.86 / 0.14 时，置信度大约 0.41，和提示词样本里的读数一致。分布越平，置信度越接近 0。

官方权重还会再乘温度。温度大于 1 把分布拉平，小于 1 把分布拉尖。多语原版三个温度都是 1，等于没做这步。温度要在留出的题上拟合；校准题少于 10 条时，拟合不可靠，本游戏因此不要拿一个固定的 0.6 去卡未经校准的置信度。

还有一个很小的 act / escalate 头，配置里 `act_costs.escalate = 0.5`、`cost_wrong_act = 3.0`。它用来表示「这题该不该交出去」。`predict()` 做选择时，本游戏没有用它当开关。

## 5. 和生成式模型差在哪

生成式模型（GPT 一类）的训练目标是猜下一个 token，使用时从左往右写。Laya 的编码器权重来自掩码语言模型（ModernBERT / mmBERT），使用时不再猜词，只给已经写好的选项打分。

因此：

- 训练 Laya 不是再做一遍语言模型预训练。微调移动的是「这段局面配哪个选项」，见微调文档。
- 它不会发明一个提示词里没有的下法。候选必须由外部准备。
- 选项一多，head 预算被平分。多语 head 256。选项 token 总和把剩余预算压到 16 以下时，进入压缩：每个选项最少留 4 个 token，指令可能被砍到 8 个 token。提示词样本里，85 个落子选项会把指令砍成 `choice question: 你是机`。仓库约定是选项压到 6–8 个；超过大约 20 个，精度会明显掉。
- 同一次 `predict` 可以带多道题，它们共享这一次编码器前向。几道题的选项都算进 head 预算。

## 6. 在这个游戏里它坐在哪

落子阶段的分工：

```text
规划器枚举当前合法落子，给每个落子打上要事标签
        │
        ▼
usablePriorities：背后至少两个落子，且落子集合不与别的要事重复
        │
        ├─ 不足 2 件 → 不调 Laya，规划器直接走
        └─ 至少 2 件 → Laya 在这些要事里选一件
                         │
                         ▼
                  规划器在这件要事里拿分数最高的那一颗骰子
```

五件要事，顺序固定（`PRIORITY_ORDER`）：

| id | 玩家看到的话 | 何时算成立 |
|---|---|---|
| `match_axis` | 配平姿态 | 已放的对手姿态能配出一个 1–6 的点数，把姿态拉回 0 |
| `clear_hazard` | 清开挡路的飞机 | 无线电能打到当前需要清的距离 |
| `landing_engine` | 着陆压速 | 着陆轮，自己的引擎还空着 |
| `equipment` | 补设备 | 剩下的起落架 / 刹车 / 襟翼，按剩余轮数已经不够再拖 |
| `fill_mandatory` | 先填必填槽 | 剩下的骰子只够放姿态和引擎 |

咖啡槽、没有目标的无线电，不进这张表。对手还没放的骰子不写进局面，也不用来判断要事是否成立。姿态是否配得平，只看已经放上去的那颗。

`activePriorities()` 数的是语义标签。两件要事可以指向同一批骰子（配平和必填槽经常重合）。这种题怎么答都走出同一个动作。`usablePriorities()` 把它们删掉。效果评估里，闸门打开之前 78% 的提问是这种假题。

默认旁路：`AI_LAYA_APPLY` 不是 `1` 时，落子仍用规划器，只记 Laya 选了什么。打开之后，还要置信度达到 `AI_LAYA_MIN_CONF`（默认 0.6）才改用它选的要事。未校准的多语原版，真题上的置信度中位数大约 0.09，这道门等于关着。

讨论、掷骰、揭晓、下一轮不经过 Laya。

## 7. 一次前向里，局面和选项怎么碰面

把示意图收成三步，对应真模型里发生的事。

**第一步，切碎片。** 局面不是一个向量。`describeState()` 的每一行会被切成很多 token：「姿态」「-1」「跑道上飞机的距离」「4」。每个 token 一个长向量。

**第二步，混在一起。** 双向注意力让「姿态 -1」影响到「配平姿态」那个 `[MASK]`，也影响到「清开挡路的飞机」那个 `[MASK]`。选项自己的文字也在 `[MASK]` 旁边，所以两个选项即使用同一段局面，取出来的向量也不一样。

**第三步，比远近。** 训练把标准答案那个选项的向量往相关碎片上拉。用的时候谁更近，谁的分数更高。两件要事的碎片同时在（又偏姿态、又有飞机），两个选项都会被拉近，分布就平，置信度就低。这时才真的需要选。

一次选择拆成多次，只在一种问法下有意义：固定顺序的两两比较（先 A 对 B，胜者再对 C）。每件要事各问一次「做不做」会全部答「做」，因为它们抢的是同一颗骰子。闸门之后多数真题已经只剩两件，再拆一次并没有新的信息。

## 8. 和本仓库文件的对应

| 文件 | 角色 |
|---|---|
| `ai/laya_service.py` | 常驻 HTTP。`POST /decide`，`GET /health`。`LAYA_CHECKPOINT` 指向本地目录时用 `laya.load`，否则用 `Router` |
| `ai/laya-client.js` | Node 客户端。不足两件真题、或熔断 30 秒内，不发请求 |
| `ai/laya-prompt.js` | `describeState` / `instructionsFor` / `renderPriorities`。选项里不写规划器分数，不写对手未放的骰子 |
| `ai/planner.js` | 要事标签、合法落子、选中要事之后的那一颗骰子 |
| `ai/ai-player.js` | 旁路或按置信度接管 |
| `ai/finetune_sky.py` | 本游戏的微调入口 |
| `test/ai/laya-finetune-data.js` | 用分叉胜率写 JSONL |
| `test/ai/laya-value.js` | 决策点分叉，量胜率差 |
| `test/ai/laya-samples.js` | 抓真实提示词 |

服务单例不是线程安全的，`laya_service.py` 用一把锁把 `predict` 串行化。
