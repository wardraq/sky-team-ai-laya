# Laya 效果评估——怎么知道它到底好不好

> 结论先行：**这个游戏没有 ground truth，"准确率"这个词不适用。** 唯一能测的是
> 决策对胜负的影响。为此建了一个「决策点分叉实验」（`test/ai/laya-value.js`），
> 用配对骰子把噪声压掉一个数量级，并自带对照组验证尺子本身是否可信。
>
> 当前读数：**Laya（未微调）的选择与规划器最优在统计上无法区分**（-1.2pp，
> 23 次真实分歧里 19 次结果完全等价）。但真正值钱的发现不在这里——见 §4。

---

## 1. 为什么不能问「准确率」

判定引擎输出的是概率分布，但**"正确选项"没人知道**。「该先清障还是先配平」
在这个合作游戏里没有标准答案，只有好坏。所以：

| 想测的 | 能不能测 | 说明 |
|---|---|---|
| 分类准确率 | ✗ | 没有标签 |
| 与规划器的一致性 | ✓ 但无意义 | 只说明它像不像规划器，不说明它对 |
| perplexity / loss | ✗ | 没有训练集 |
| **对胜负的影响** | ✓ | **唯一真值** |

所以问题要重新表述成：**在有它的地方和没它的地方，胜率有没有差别。**

---

## 2. 为什么整局胜率太钝

早期试过直接比整局胜率（AI+Laya vs AI 单跑）。不行，原因是两层漏斗：

```
全部决策点
  └─ 只有 17% 会去问 Laya（成立的要事 ≥2 件）        ← 第一层漏斗
       └─ 其中只有约 2.4% 会真的改变落子              ← 第二层漏斗
```

整局胜率只能看到这 2.4% 的**最终加权效果**，被 97.6% 的噪声盖住。要分辨一个 2%
的胜率差，在 45% 基线上需要约 **9700 局/臂**——跑得动但没有意义，因为单个决策
的效果被稀释在整局里，你永远不知道是哪一步起了作用。

---

## 3. 决策点分叉实验

把测量**下沉到决策点**：

```
   固定一个决策点（状态冻结、骰子已掷出）
        ├─ A 臂：规划器的答案 ──┐
        └─ B 臂：被测评的答案 ──┤  用同一批骰子，各跑到终局
                                ↓
                    比胜率 → Δ 就是这个选择值多少
```

**两个关键设计：**

**① 配对骰子（common random numbers）。** 游戏里每一个骰子都走
`game-logic.js:111` 的 `d6() → Math.random()`。把它换成可播种的随机流，两条路就能
拿到**同一批骰子**。这样骰子方差在两条路之间抵消，同样的局数下灵敏度高得多。

> 前提：规划器在一次决策中不能消耗这条流。已核实 —— `rollout` 受 `guard < 20`
> 约束只走完本轮，掷骰分支不触发。规划器自己的策略噪声（对手建模、同分兜底）
> 通过新增的 `Planner.setRng()` 摘到另一条流上，不再干扰配对。

**② 必须带对照组。** 这是最容易被跳过、但最关键的一步：**你得先证明尺子能分辨好坏。**
所以每轮都同时测两个已知很差的臂：

- `规划器最差`：规划器打分最低的那个落子（下界）
- `随机合法`：随机挑一个合法落子
- `逐颗贪心`：`quickMove`，单跑整局胜率 0%

如果尺子量不出它们差，那就没资格去量 Laya。

## 4. 实测结果

服务端：`convaiinnovations/laya` 多语 checkpoint（322M），M4 MPS，单次 ~50ms。
规划器设置与线上一致（`fair:false, coop:1, samples:1`）。

```
采样 150 个「Laya 会被问到」的决策点，每个岔路口跑 40 局

  臂            决策点  同选   参照胜率  该臂胜率     Δ      更优 更差 持平
  ----------------------------------------------------------------------
  逐颗贪心          150    77    46.7%     46.2%   -0.5pp     5    4   64
  规划器最差         150    26    47.8%     28.4%  -19.5pp    15   65   44
  随机合法          150    74    47.1%     34.5%  -12.6pp    10   36   30
  Laya 的选择        34    11    46.7%     45.5%   -1.2pp     2    2   19
  ----------------------------------------------------------------
  共 11840 局
```

**尺子自检通过**：对照组被量出 -19.5pp / -12.6pp，说明这把尺子能分辨好坏。

**Laya 的读数**：在被问到的 34 个点里，11 次与规划器同选、23 次真的换了落子。
这 23 次里 **19 次结果完全等价**，2 次更优、2 次更差，净 **-1.2pp**。

`-1.2pp` 这个数不要过度解读：23 个分歧点、2 比 2，统计上与 0 无异。
**诚实的结论是「无法区分」，不是「略差」。**

### 但这一节真正的发现是这个

```
【问题质量】Laya 被问到的这些局面，有多少是真的选择题
  要事标签数 ≥2 但动作集合重复（假题）：117/150  (78%)
  真的有两套不同动作可选（真题）：       33/150  (22%)
```

**78% 的调用是在问一道假题。** 原因是 `activePriorities()` 数的是**语义标签**，
不是**可选动作集合**：

- **63%** 的情况：某件要事背后只有 0~1 个落子 —— 选它和选谁都一样
- **18%** 的情况：两件要事指向**同一批落子**（`match_axis` 和 `fill_mandatory`
  在必填槽未填时几乎总是重合）

这样的题无论模型怎么答，规划器都只能走出同一个动作。**一次 50ms 的前向白烧，
而且是 78% 的概率白烧。**

---

## 5. 修复：可用性闸门

在 `ai/laya-client.js` 里加了 `usablePriorities()`：只有**背后有两个以上落子、
且与其他要事的落子集合不重复**的要事，才算一道真题。不足两件就直接返回，
不调 laya。

实测效果：

| | 修复前 | 修复后 |
|---|---|---|
| 发问率 | 100%（有 ≥2 个标签就问） | **23%** |
| Laya 选择分布 | 配平姿态 86% / 着陆压速 13% | 配平姿态 71% / 着陆压速 29% |
| 与规划器选的要事一致 | 56% | **35%** |
| 最终落子与规划器相同 | 56% | 32% |
| confidence 中位数 | 0.17 | **0.09** |

修复后的画风变化很说明问题：去掉假题之后，Laya 和规划器的分歧率从 44% 升到 65%，
但它的 confidence 反而**更低**（中位 0.09，71% 低于 0.2）。

翻译过来就是：**它只在真正有选择的地方开口，却恰好在自己最没把握的地方开口。**
这符合预期——没微调过的模型面对这个游戏的领域判断，本来就该是"不知道"。

## 6. 复现与日常使用

```bash
# 1) 起判据服务（首次下载权重）
LAYA_PRELOAD=multilingual python3 ai/laya_service.py

# 2) 跑分叉实验：决策点数、每臂局数
node test/ai/laya-value.js 150 40
# 产出 test/ai/.laya-value.json（含每个决策点的明细，可自行切分）
```

服务不在时会自动跳过 Laya 臂，只跑对照组——所以随时可以跑，不会卡住。

**改了什么之后该重跑**：换指令版本、换 checkpoint、微调之后、改 planner 评分函数。
每次约 5 分钟。

## 7. 局限（必须一起读）

1. **参照臂是规划器，不是真理。** Δ 衡量的是"相对规划器最优的得失"，不是绝对好坏。
   如果规划器本身有系统性盲区，Laya 恰好补上了，这个实验会把它记成"零收益"。
2. **每臂 40 局，单点分辨率粗。** 单点 Δ 的粒度是 2.5pp，只有聚合到几十个点才有意义。
3. **延续策略用的是规划器自己。** 两条路后续都由规划器接手，所以测的是"这一步的影响"，
   不含"Laya 后续会走出一条不同的路"这种二阶效应。
4. **`fair:false`（全知视角）。** 与线上默认一致，但意味着双方都能看到对手未放置的骰子。
   要测公平视角加 `fair:true`，代价是胜率大幅下降（见 `docs/ai/AI陪玩.md`）。
5. **19/23 结果等价不是实验缺陷，是游戏性质。** 前面已经独立验证过：本轮内只要资源够，
   不同顺序会到达逐字段相同的终态。**这意味着任何决策者的改进上限都受限** ——
   在一个大量决策"顺序无关"的游戏里，选得更准也换不来多少胜率。

---

## 8. 所以，回到问题本身

**怎么知道 Laya 好不好？** 三步：

1. **承认没有准确率。** 把问题改成"对胜负有没有影响"。
2. **在决策点上量，不在整局上量。** 配对骰子 + 对照组。
3. **先量对照组。** 尺子量不出「规划器最差」的话，它给出的任何 Laya 结论都是噪声。

当前三步都做完了，答案是：**未微调的 Laya 在这个游戏上还没有可测量的贡献，
但也没有明显损害；而它在 78% 的情况下根本没被问到有意义的问题——那是更该先修的地方。**

修完之后，它的真实位置才第一次显形：一个在 23% 的决策点上、以 0.09 的自信度
和规划器唱反调的判定器。**这就是一条可以开始微调的基线。**
